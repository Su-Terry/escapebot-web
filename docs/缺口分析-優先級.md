# EscapeBot 缺口分析（兩軸並行 · 各自 Ship 線）

> **框架**：把優化拆成**兩條不互相排序的軸**——
> - **軸 A｜Viral（吸引 / 傳播）**：讓玩家進來、想分享。北極星「值得分享」。
> - **軸 B｜流失（留得住）**：別讓玩家因設計不良走掉。標準「有多少玩家因謎題設計不良流失」。
>
> 兩軸衡量**不同面向**，不放同一隊列比誰前誰後。這化解「賣貓還是賣密室」的偽二選一——**不選**：貓/互動負責 viral，謎題負責不流失，各自達標即可。
> 兩軸**各有 ship 閘門，兩個都過才丟玩家**。判斷用直覺，不是檢查表。

## 軸 A｜Viral（吸引 / 傳播）
> **Ship 閘門（直覺）：玩完，你自己會不會想把某個東西傳給朋友？講不講得出一句「我剛剛……」。** 講不出 = 還沒到。

分兩種爆點，**時間差不同**：

### A1 互動爆點（「第一次看到就想傳」）— 其實已做好，要當資產看
- 捏包子 → 彈弓 → 貓吃 → 貓吐 這條鏈。「我把一句話捏成包子射給貓」本身就夠怪、第一次看到就想傳。
- EscapeBot 最獨特的是**互動方式**，不是 AI 生成的內容（interaction-first，像 Wordle 傳格子不傳答案）。
- **已完成**（M3 + 3D）。缺的是**意識到它是最強 viral 資產、去放大它**（分享時把這個互動本身講出來，而不只給張結果卡）。
- 槓桿：高 ｜ 成本：低（已做，差包裝）。

### A2 內容爆點（「玩久了才想傳」）
- **貓人格**：可轉述句子的來源。**聲音已拍板(2026-06-02,G-catvoice ✅)——「認真但奇怪的世界代理人」**(擬人化世界、誠實回報、偶爾一絲乾、不毒舌;persona 已接 Phase4 narration、實玩驗過,見設計文件「三點五、貓的聲音」)。A2 不再卡聲音。剩 weird/黃金/腐爛包(截圖理由,與貓人格一體)牽「誰標類型」→ engine。
- **weird / 黃金 / 腐爛包**：截圖理由。與貓人格一體（腐爛包配一句台詞 = 一個完整事件）。牽「誰標類型」→ engine。
- 槓桿：高 ｜ 成本：中。

### A3 內容供應 / 第二次分享
- **Replay（重玩）— ✅ 已完成(2026-06-02)**：程序生成產品鐵律——每次不同 → 重玩不是附加功能，是**內容來源**（Roguelike / AI Dungeon 同理）。沒 replay = 沒第二次故事 = 沒第二次分享。**提前到與 A2 同級**（原本低估）。已落地：分享連結變進入點，B 能玩 A 那關的乾淨副本、自己 diverge，且可傳遞 A→B→C（實作見 BACKLOG F-replay）。
- **滿地包子卡 / 金句卡**：分享物（滿地卡依賴生成修好）。
- 槓桿：中高 ｜ 成本：中（replay ✅ 已做）。

### A4 場景辨識度（不是美術 polish）
- 「我剛剛在貓的大腦裡解謎」可傳；「研究室背景比較精緻」不可傳。**辨識度是內容、不是 polish。**
- 牽 **generator**：要生成有強 identity 的怪地點（貓的腦袋 / 鯨魚肚子 / 壞掉的販賣機），不是事後貼背景圖。連動「謎題多樣性」（同一個 generator 創意源頭）。
- 槓桿：中高 ｜ 成本：中（牽 generator）｜ **需料**：你 generator 現在產出的場景有沒有 identity，我沒看過樣本。

## 軸 B｜流失（留得住）
> **Ship 閘門（直覺）：有沒有玩家會因為謎題/體驗爛到想關掉？** 衡量**流失嚴重度**，不是「可解性百分比」。偶爾不可解、玩家聳肩重開（尤其有 replay）= 可接受；爛到「覺得這遊戲在唬爛」再也不回 = 致命，要修。

### B1 謎題合理性 / 可解性（用流失衡量，不追求 100% 可解）
- generator 設 solution 但不驗證「線索能否推出答案」。一批 bug：F-spoil、容器鎖、重複 item、位數不符、鑰匙語意。
- 尺：**修到「不會讓人想關掉」**，不是完美。致命流失的先修，沒到的晚修。
- 早期用直覺（這謎題爛到會讓人走嗎）；有玩家後看實際流失到第幾關。
- 徹底解 = Phase 3 因果圖（護城河，不擠現在；長期也是未來付費 host 的「可解性保證工具」——見設計文件長期方向）。

### B2 遊戲理解（懂不懂這是解謎）
- 可愛蓋過「這是密室逃脫、要解謎逃出」→ 玩家以為是餵貓玩具 → 玩兩下走掉。
- **已有玩家證據**：Player S(Phase 1 老玩家回流)反覆卡「貓吃包子為啥推進度、邏輯呢」——隱喻沒接上(見 BACKLOG Player S evidence)。不再只是「需料」,有真實訊號。
- **斷點精確定位**：玩家把貓理解成「會吃包子的觀賞型 NPC(跑劇情動畫)」,而非「執行你行動的代理型系統」。卡在「為什麼餵貓=系統行為發生」這一步的合理性。
- **候選手段(磚頭,待實測,別假設一句解決)**:開場給一個極短的**語意錨點**——「這裡不收文字指令,你的指令就是包子;捏成包子給貓,貓把它變成這世界能理解的行動」。把規則先定義成系統隱喻(包子=行動語言),玩家就從「為什麼餵貓推進度?」轉成「我這想法會變成什麼結果?」。副作用好:玩家能自然轉述「不是打指令,是把想法捏成包子丟給貓、它改變世界」(餵養 A1)。
  - **注意**:錨點要用**貓人格**講(in-character),不是功能說明書語氣——否則解 B2 傷 A2(貓人格味道)。貓聲音已拍板(G-catvoice ✅,認真但奇怪的世界代理人,見設計文件三點五),B2 錨點不再卡聲音 —— 可直接用這個人格寫開場錨點。
  - **別過度樂觀**:一句宣告對「沒讀到規則」的新玩家可能有效,對「品味上不買單隱喻」的人(如 Player S 偏動作向)未必。做了要實測新玩家還卡不卡,不是做了就解決。

### B3 prefill 輸入建議 — ✅ 已完成(帶缺陷,見 B0)

### B0 engine visibility 模型 / 逐步揭露 — ✅ 已完成(2026-06-02)
- **缺陷(已解)**:engine 原本沒有「物件被發現了沒」的概念——所有物件進房全可見、全可 take。prefill 查看 chip 把這缺陷攤出來。
- **做法**:Item 加 hidden + belongsTo,hidden 由 deriveHiddenFields 從 belongsTo 推導(LLM 只填 belongsTo、不填 hidden,從結構杜絕不一致);examine 家具 promote 其 hidden children;toView/context 依 visibility 篩。(實作見 BACKLOG F-visibility;examine 時序補丁已被下方四拍重構吸收。)
- **待補**:reward item 的「solve 揭露」這條路徑(reward 解謎前不該可見)→ 見軸 B 新順序第 1 項 / BACKLOG F-reward-reveal。

### B0.5 回合處理四拍重構 — ✅ 已完成(2026-06-02,根治一族 coupled 流失)
- **解什麼**:LLM 演假成功(假 solve / 假 move)、narration 領先 state、snowball——玩家以為解開了/進房了但 engine 沒動,繼續玩發現對不上 → 「覺得遊戲在唬爛」的致命流失。石門事件的 A 半。
- **做法**:回合處理改「意圖→判定→敘述」四拍,narration 永遠在 state 定案後生,solve 走獨立 judge(verdict 三路 solved/ambiguous/wrong)。實玩驗過假 solve/假 move 不再發生(見 BACKLOG F-turnloop-v2)。
- **路線定位**:屬 Phase 2,但**是 Phase 3 因果圖「判定結構化/可驗證」那一面的前身**(judge 結構化判定、state 權威 = 因果圖可達性判定的同源思路)。Phase 3 因果圖的另一面「謎題生成可解」(下方軸 B 新順序第 3 項)四拍沒碰、仍待。
- **殘留**:Phase 4 narration 仍自由 prose,acknowledgedOutcomes 抓顯性假成功、抓不到「模糊暗示」細縫(prompt 壓 + 實玩抓,傷害遠小於石門)。
